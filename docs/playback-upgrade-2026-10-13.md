# NASMusicBox 播放升级交付与验证

## 使用

在项目根目录运行 `start-desktop.bat`。现有收藏、下载和歌词入口沿用。搜索选“综合”时两平台陆续出结果；同曲条目可展开音源。播放器右侧打开“播放队列”进行下一首、追加、拖动排序、移除或清空；“音效”打开九种预设与原声。退出后重新打开会恢复队列和进度，保持暂停，点击播放时重新解析临时地址。

## 本次实现

- `/search/stream` 并行请求 QQ/YouTube，以 SSE 渐进发送结果；已有 `/search` 保持兼容。相同标题、歌手和版本且两边有可靠时长、差值不超过 `max(3 秒, 2%)` 才自动合并。现场、翻唱、混音和伴奏等版本分开。
- `/visualize` 增加快速解析、候选音源和刷新选项；取色单独请求。`/playback/prepare` 为实际下一首尝试读取 Range 前缀；远端忽略 Range 就仅保留解析信息。媒体统一由本地代理进入 Web Audio，保留拖动所需的 Range。
- 主界面、氛围模式、迷你窗口、桌面热键和托盘调用同一队列状态。随机一轮不重复，上一首按播放历史；单曲循环只作用于自然结束。移除当前项会转到下一项，空队列停止。会话使用原设置表保存版本化元数据，不保存临时签名音频 URL。
- 九种音效实际走 Web Audio 处理链，选择自动保存，80 ms 过渡，并带输出峰值保护和失败旁路。具体参数见 `frontend/src/audio/README.md`。预设是独立调音，不能称为汽水原版还原。

## 验证结果

在 2026-10-12 同机对照原 Git HEAD 基线与升级版。受控服务为**相同程序音频、相同模拟音源解析约 250 ms 与取色约 550 ms**，每版 5 次，点击后计时到音频元素 `playing`。每次重置服务端缓存，点击当前歌曲后留出 1.3 秒准备下一首。原版 / 新版的预热下一首中位数为 **890.1 / 28.7 ms，减少 96.8%**，超过 30% 目标。冷歌中位数为 **3765.9 / 2008.3 ms**；冷歌波动较大，在线实测不应套用该比例。逐轮数值见 `output/upgrade-2026-10-12/browser-verification.json`。

相关检查：后端 **70 项**，队列/渐进搜索 **7 项**，音效离线样本 **83 项**，真实媒体元素/Worklet **39 项**，前端构建通过。受控浏览器覆盖双源渐进合并、九预设选择、手动换源续播、重启暂停恢复、队列重排/删除/循环、迷你窗口与氛围模式联动、快速点歌意图。另对代理返回真实 403 做了刷新地址、严格切至已验证同版本音源、恢复原进度的浏览器检查。详见 `browser-verification.json`、`recovery-verification.json`、`audio-verification.json`。

收藏显示及播放、历史记录、氛围模式同步歌词和下载任务均走过浏览器实际界面，下载文件写入 D 盘隔离目录。检查时修复了下载接口同步等待远端响应造成的后端阻塞，记录在 `regression-verification.json`。

Windows 桌面 WebView2 实测了播放时间推进、3D 音效、托盘/热键调用的下一首、原生迷你窗口暂停主音频，页面没有未捕获异常；`windows-verification.json` 有事件与时间数据。该桌面测试使用隔离资料库及受控原创 WAV。

真实线上搜索“晴天 周杰伦”：QQ 约 0.58 秒先返回 3 项，YouTube 约 7.7 秒后补齐到 7 个保守分组；QQ 测试曲目播放地址未返回完整 `purl`，YouTube 解析成功，本地代理通过 HTTP 206 读取了前 32 KiB。见 `online-verification.json`。线上网络波动、地域及账号权限会影响实际可播放性。

真实 YouTube 浏览器播放随后进入了 `playing`，音频可推进，网页无未捕获异常。本次在线冷播放约 **32.4 秒**：解析约 8.2 秒，之后等到首个可解码数据约 24.2 秒，详见 `online-browser-verification.json`。这是当前网络/音源条件的一次观察值，显示在线冷启动仍有较大延迟；受控环境下 96.8% 的预热收益不可替代这个事实。

九种预设和原声的 9 秒原创音乐试听文件在 `output/upgrade-2026-10-12/audio-previews/`，按 RMS 匹配响度。尚未完成使用同一受许可歌曲在汽水和 NASMusicBox 上的响度匹配 A/B，也没有本人桌面音箱试听记录，所以“接近汽水”的主观程度仍待用户试听。REA 证据见 `docs/REA-2026-10-12.md`。

所有 QA 资料库、脚本、截图及试听文件位于 D 盘 `output/`，与日常资料库隔离。未创建 GitHub Release。
